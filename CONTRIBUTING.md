# Contributing

Start with an issue for a bug, feature proposal or macOS port.
Fork the repository, create a branch, make a focused change, run relevant
tests, and open a pull request against main. Explain what changed, why,
and how you tested it. Use synthetic notes in screenshots.

The maintainer reviews pull requests before merging; forks do not grant
write access to this repository.

Preserve local-first saving, stable note IDs, offline queues, lossless text,
accessibility and comfortable performance. Never commit OAuth JSON, tokens,
browser profiles, private notes or accounts. Do not post real notes in issues.

Code contributions use MIT. New media needs clear provenance and terms
compatible with ASSETS-LICENSE.md. Keep dependency notices.

Useful starting points: a tested macOS host, readable native code,
accessibility, localization and installer tests.
